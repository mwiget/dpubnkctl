### Observations after wizard

The wizard answered everything it knows how to ask. Validate at the
end shows **0 errors, 10 warnings**. The warnings are all things the
wizard *doesn't* ask about and the operator has to fill in by hand:

1. `metadata.customer` — wizard never asks.
2. `network.internal_cidr` — template default, never asked.
3. `network.cluster_apiserver_address` — wizard doesn't ask; this is a
   per-deployment choice (data-plane subnet, one of the host IPs).
4. `network.node_ip_role` — wizard doesn't ask; binds kubelet --node-ip
   to either mgmt or a data-plane VLAN.
5. Per-host `data_plane.parent_iface` + VLAN list — wizard doesn't ask
   for any of this even though it discovered the host's interfaces.
6. Per-DPU VLAN list — wizard merges the DPU PCI/mode/lag but not the
   VLAN config the operator needs to plan.
7. `bnk.external_selfip` / `bnk.internal_selfip` — wizard doesn't ask;
   `deploy cne` will fail without them per the warning text.

**This is the biggest UX gap exposed by the test**: the wizard's promise
("interactive discovery") implies it gets you to a deployable PoC, but
it really only fills in hosts[] (with SSH + DPU PCI). Network plan
remains 100% manual. Either the wizard's scope should extend, or the
documentation has to be explicit ("wizard only covers steps 1–5 of N").

## Verdict on the human, non-agentic workflow

`dpubnkctl wizard` + manual poc.yaml fill + `dpubnkctl e2e --yolo`
**does** produce a working 2-node BNK cluster end-to-end. The wizard
correctly bootstraps the hosts[] block, all 7 wizard fixes from
yesterday's test pass hold, and the e2e pipeline executes every phase
in the right order. Resume-after-failure also works as advertised.

But the workflow has three sharp edges that hurt unaided operators:

1. **Wizard's scope is small** (issue #11). 80% of poc.yaml — the
   network plan, self-IPs, VLAN topology, cluster apiserver address —
   is still hand-edit territory. A new operator without a reference
   poc.yaml or an agentic CLI would be reading `network-design-checklist.md`
   and `examples/*.yaml` to fill in the blanks. The wizard could go
   farther.

2. **Mid-pipeline manual reboot kills `--yolo`** (issue #13). DPU first-
   flash leaves the host PF in a ghost state that only a host reboot
   clears. The recovery code already detects this and helpfully says
   "reboot the host manually" — but for a `--yolo` flow the right move
   is to do the reboot automatically.

3. **Stale cross-references in error messages** (issue #12). Easy to
   fix individually, but worth auditing once across all `AGENTS.md #N`
   pointers.
